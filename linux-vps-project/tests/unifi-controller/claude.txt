     Plan: Create resolution.md for UniFi + MongoDB Docker Setup

     Context

     The user attempted to deploy UniFi Network Application with MongoDB but
     combined them incorrectly, resulting in a "wrong password" connection
     error. The goal is to produce a clear, correct resolution.md file they can
     follow on their Linux VPS — no commands will be executed locally.

     What resolution.md will contain

     1. File layout

     Two files to create on the VPS:
     - docker-compose.yml — both services with a shared network
     - init-mongo.sh — MongoDB user init script

     2. init-mongo.sh (verbatim from linuxserver docs)

     The script uses mongosh or mongo depending on version, reads env vars, and
     creates the unifi user with dbOwner on four databases: unifi, unifi_stat,
     unifi_audit, unifi_restore.

     3. docker-compose.yml

     Two services:
     - unifi-db: mongo:7.0 (pinned), env vars for root and app credentials,
     volume for /data/db, init script mounted as :ro at
     /docker-entrypoint-initdb.d/init-mongo.sh
     - unifi-network-application:
     lscr.io/linuxserver/unifi-network-application:latest, env vars pointing
     MONGO_HOST to unifi-db, all required ports

     Both share a user-defined bridge network so the app can resolve unifi-db by
     name.

     4. Deployment steps (ordered)

     1. Create directory structure and files
     2. docker-compose up -d unifi-db — start DB first, let init script run
     3. docker-compose up -d unifi-network-application — start app after DB is
     healthy
     4. Access UI at https://<vps-ip>:8443

     5. Pitfalls section (root cause of original error + other gotchas)

     - Init script only runs on a clean /data/db — if DB was started without it,
     must wipe volume and restart
     - MONGO_AUTHSOURCE=admin is required (not the app db name)
     - Env vars are only read on UniFi's first run — changing them later
     requires clean /config
     - MongoDB version must be pinned; never use latest
     - Port 8080 must not be remapped
     - Device adoption requires setting Inform Host in Settings > System >
     Advanced
